# Job elements

This chapter provides comprehensive guidance on the essential elements within CloverDX, which are crucial for designing and managing data transformation jobs, enabling effective data integration and processing workflows.

- [**Components**](components.md) are the building blocks of CloverDX jobs, performing various [data transformation tasks](components.md#component-types). This section covers how to [add](components.md#adding-components) components, [edit their properties](components.md#edit-component-dialog), and [enable or disable](components.md#enabledisable-component) them based on specific conditions. You will also learn that some components have [metadata templates](components.md#metadata-templates).
- [**Edges**](edge.md) connect components and define the flow of data between them. This section explains how to [create and manage edges](edge.md#connecting-components-with-edges), [assign metadata](edge.md#assigning-metadata-to-edges), and what [edge types exist](edge.md#types-of-edges). You will also learn about [edge memory allocation](edge.md#edge-memory-allocation) and debugging techniques, such as using the [Data Inspector](edge.md#data-inspector) or adjusting the [default debug properties](edge.md#selecting-debug-data) .
- [**Metadata**](metadata.md) defines the structure of data processed within CloverDX jobs. This section introduces the [Metadata Editor](metadata-editor.md) and its key functionalities. It covers various [metadata types](metadata-types.md), including [internal](metadata-types.md#internal-metadata), [external (shared)](metadata-types.md#external-shared-metadata), and [SQL query metadata](metadata-types.md#sql-query-metadata). This section also introduces the different ways to [create metadata](creating-metadata.md). Additionally, it discusses [metadata propagation](auto-detected-metadata.md), how to [change or define delimiters](changing-and-defining-delimiters.md), or how to set up [multivalue fields](multivalue-fields.md).
- [**Connections**](connections.md) allow CloverDX to interact with external systems and data sources. This section provides detailed information on configuring different types of connections, including [database](database-connections.md), [JMS](jms-connections.md), [QuickBase](quickbase-connections.md), [Hadoop](hadoop-connections.md), [Kafka](kafka-connections.md), [OAuth2](oauth2-connections.md), [MongoDB](mongodb-connections.md), and [Salesforce](salesforce-connections.md) connections. Each type of connection is explained with instructions on how to set up and manage it effectively.
- [**Parameters**](parameters.md) are constants or macros you define once and reuse throughout your graph configuration. This centralized management allows you to easily update values in one location without modifying them in multiple places. This section explains how to [create](parameters.md#creating-parameters) parameters, describes the difference between [internal](parameters.md#internal-parameters) and [external (shared)](parameters.md#external-shared-parameters) parameters, and explains the importance of [secure parameters](parameters.md#secure-graph-parameters) to encrypt sensitive data. Additionally, it covers [dynamic parameters](parameters.md#dynamic-parameters-parameters-with-ctl2-expressions), whose values are calculated based on a CTL formula, and [environment variables](parameters.md#environment-variables), which are defined outside of CloverDX within the operating system. Additionally, it explores [built-in](parameters.md#built-in-execution-parameters) execution parameters that can be used to tailor job behavior further within CloverDX.
- [**Sequences**](sequences.md) are designed to generate a sequence of numbers, which can be used for tasks like generating unique identifiers for records. This section discusses the different types of sequences, including [persistent](sequences.md#persistent-sequences), [non-persistent](sequences.md#non-persistent-sequences), [internal](sequences.md#internal-sequences), and [external (shared)](sequences.md#external-shared-sequences) sequences, and how to manage them.
- [**Lookup tables**](lookup-tables.md) are data structures used to map input data to corresponding values, facilitating efficient data transformation processes. Lookup tables can be accessed using CTL functions and may store data in files, databases, or cache memory. This section covers the different types of lookup tables: [Simple lookup](lookup-tables.md#simple-lookup-table), [Database lookup](lookup-tables.md#database-lookup-table), [Range lookup](lookup-tables.md#range-lookup-table), [Persistent lookup](lookup-tables.md#persistent-lookup-table), [Aspell lookup](lookup-tables.md#aspell-lookup-table) tables. These lookup tables can be [internal](lookup-tables.md#internal-lookup-tables) or [external (shared)](lookup-tables.md#external-shared-lookup-tables).
- [**Notes**](note.md) are used to add annotations and documentation directly into CloverDX jobs. This section describes how to [place](note.md#placing-notes-into-graphs), [resize](note.md#resizing-notes), [edit](note.md#editing-notes), and [format](note.md#formatted-text) or [change properties of notes](note.md#notes-properties), as well as how to [use links](note.md#links-from-notes) and [fold notes](note.md#folding-notes) for better graph organization and readability.
- A [**Dictionary**](dictionary.md) in CloverDX is a data storage object associated with each job run, designed to provide simple and type-safe storage for various parameters required by the job. It is not limited only to input or output parameters but also facilitates sharing data between different components within a single job. This section guides you on [creating](dictionary.md#creating-a-dictionary) and [using dictionaries](dictionary.md#using-a-dictionary-in-graphs) effectively in your projects.
- [**Execution properties**](jobconfig.md) are configurable parameters that control various aspects of how a CloverDX job is executed, such as logging levels or concurrency limits. This section provides a [list of available execution properties](jobconfig.md#list-of-execution-properties) and their descriptions, and instructions on how to set them up [in the Designer](jobconfig.md#setting-execution-properties-in-designer) or [Server environment](jobconfig.md#setting-execution-properties-in-server-console).
